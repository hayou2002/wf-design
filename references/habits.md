# 设计工作流 · 经验与偏好

只保留跨任务仍有效、且未在主流程或技能本体中完整覆盖的经验。主流程已有规则不在这里重复。

## 表达与取舍

- 用户说“你定”时，AI 先筛选少量候选并说明理由，再让用户选参考或确认样板；不反复追问术语，也不靠跳过确认减少步骤。
- 先排视觉再补文案，文案一改版式容易全塌。先把标题、按钮和关键说明定下来，再排。
- 内容装不下时先删、拆页或换表达，不靠缩小字体硬塞。
- 不用大卡片冒充高密度表格；是否高密度要看真实页面的比较效率。
- 术语只补认知，不因为刚学到一个新词就强换设计或技术。

## 视觉与素材

- 交付前必须真看过；打不开、没有看图能力时明确写“视觉未验证”，不能把文件生成成功当成视觉通过。
- 品牌标识用官方素材，不自己画“差不多像”的。
- 生成图里的文字逐项核对，错字整张重做，不另贴一层字盖住。
- 笔记里的技术图不一定有透明通道，不拿普通配图的透明检查规则套它。
- 生图通道不可用时，只阻断依赖生图的部分；其余可验证工作继续，并说明缺口。

## 项目与协作

- 样板一旦铺满全部页面或状态，就失去了降低返工成本的意义；只覆盖能决定方向的最小范围。
- 多 Agent 同时修改共享规范、共享样式或页面地图会造成事实分叉；一个切片一个工作区，共享文件只有一个写入负责人。
- 子 Agent 自报完成、单测通过、截图生成、生产生效是不同证据，不能互相替代。
- 子 Agent 没有持续回报时标状态未知或超时，不把“仍在运行”当成“进展正常”。
- 项目状态导览由结构化数据复用模板更新；内容未变不反复打开浏览器重画。

## 参考与工具

- 先给真实参考，再做关键样板；只有链接或仓库列表不等于用户能判断方向。
- 把设计稿字段、函数或组件能力当成事实，会让执行者照错误契约开发；交接必须区分事实、建议和待核实项。
- 参考库不是越大越好；能按问题找到具体证据比来源数量重要。
- 安装能力 Skill 后要反推它改变了哪个判断或验收点，不能只登记名字。
- 困难来源优先使用现成官方接口或保留链接，不从零开发抓取与截图工程。
- B 站检索是本工作流工具，不是独立设计 Skill，也不是每个任务的必经步骤。
