# 设计工作流 · 习惯与注意事项

每踩一次坑就往这里追加一条，写清「什么情况、怎么错、正确做法」。下面是初稿，用着用着按实际情况改。

## 红线

- 每趟先取舍：用不到的技能不读、不写进本次记录，也不为了「走全流程」硬凑；动手前一句话说明这次用了哪些、哪些不用、为什么。
- 先定类型再定档：有 SOP 只读命中的那一份；没有就按底座走，不临时拼一套新流程。
- 分档看可观察条件，不靠感觉：来源数、字数、是否重排、图数、是否对外；对外发布不能降到 L1。
- 文字也是设计：读者会看到的字按 oil-tone 写，字号、行距、层级归 oil-ui-pro 或文档能力管，别用「排版好看」代替「话说清楚」。
- 写入远端前先确认目标：父文档下新建、具体子文档追加、同名追加，不重复建；覆盖和删除先问。
- 不编内容：材料里没有的事实、数字、客户名、评价和服务名单都不补造。示例内容交付前必须清干净。
- 不做没用完的装饰：加图形、加动画、加色块之前先问它帮读者明白了什么，答不上来就不加。
- 超了先砍内容，不缩字号：内容装不下时删、拆页或换表达，不靠缩小字体塞进去。
- 交付前必须真看过：打开浏览器或截图算看过；打不开、没有看图能力时，明说「视觉未验证」，不把「文件生成成功」当成「做完了」。
- 不动用户的存量页面：新建另存，不覆盖、不挪动；要不要替换原来的入口，交付时问用户。
- 品牌标识用官方素材，不自己画一个「差不多像」的。
- 生成图里的文字要求模型直接画在图上，不另贴一层字盖住；错字要整张重新生成。
- 凭据值不写进工作流、清单、对话和日志；只写「需要什么、放在哪」。
- 花钱的动作先小样：要按次计费的生图或生视频，先做一小段确认效果，再批量生成。

## 踩过的坑

- 一次铺开做很多页，改方向时全部返工。先做一屏或一页，检查过再照结构铺开。
- 只凭代码想象效果，以为对齐了、其实挤在一起。必须打开或截图看真实渲染。
- oil-html 那套分享文档不主动触发。用户只说「做个页面」时走网页车道，不要自己上白底黑字网格那套。
- 一键式把「你定」当成了反复确认。用户说「你定」就直接定方向并说明理由，别再问。
- 生成图的标签容易出错字，尤其中文。交付前必须逐字核对，不能只看整体像不像。
- 生图默认走 MCP 的 `magpie-image`，不用另外配 Key；这条通道不可用时只影响生图，把不依赖生图的部分做完并说明差哪一项，别一句话说成全都做不了。
- 先排视觉再补文案，文案一改版式全塌。先把标题、按钮和开场定下来，再排。
- 思源写入不要把 token 拼进临时命令或贴进对话；统一走 `scripts/siyuan_note.py`，它从本地配置读凭据且不回显。
- 笔记里的技术图不一定带透明通道，不要拿 `design_check.py` 的 PNG 透明检查去验普通配图；笔记用 `note_check.py`。
