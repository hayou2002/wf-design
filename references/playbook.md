# 设计工作流 · 详细步骤

命令里的 `<技能目录>` 指这份工作流自己的目录，产出自检用 `scripts/design_check.py` 或 `scripts/note_check.py`；`<某技能目录>` 指对应技能自己的目录。

## 目录

- 名词速查（不懂就看这里）
- 取舍规则（每趟先做这一件事）
- 按类型调用 SOP（先定做什么，再定产出）
- 底座（每趟都走）：问清用途 · 定方向 · 做第一版 · 看一眼再改 · 交付与自检
- 车道 ① 网页与界面
- 车道 ② HTML 文档与演示
- 车道 ③ 图片、图标与插画
- 车道 ④ 正式文件
- 下一步可以补什么

## 名词速查（不懂就看这里）

- 设计稿 / 效果图：一张画好的界面图，好看但不能点。
- 落地页：一整页把产品讲清楚、让人愿意点的网页。
- 风格方向：同一件东西的几种不同长相，先挑一种再往下做。
- 对比页：把几种风格并排放在一页上，方便挑。
- 透明 PNG：背景是透明的图，叠在什么底色上都不带白框。
- SVG：矢量图，放大不模糊，适合徽章、线条和简单图形。
- 16:9：幻灯片常见的横版比例。
- 动效：元素怎么出现、怎么过渡，不属于内容本身。
- 拟真 UI：用手写 HTML/CSS 画出来的假界面，用来演示，不是截图。
- 自检：交付前跑一遍脚本，把明显的坑先挑出来。

## 取舍规则（每趟先做这一件事）

不把四条车道和十几个技能整包带上。每趟动手前：

1. 定类型：这次是笔记整理、文档整理、内容排版，还是别的。
2. 定档：按可观察条件判 L1/L2/L3；档位决定要不要停、停几次。
3. 定车道：这次要交的是哪一类东西。
4. 逐条过技能，判「这次用得上吗」。用不上就不读、不写进本次记录，也不要为了走全流程硬凑。
5. 告诉用户结论：这次用哪几个、哪几个不用、为什么。一句话就够。

判断不了的先读那个技能的说明再定，不要先全读完再判断。

| 技能 | 什么情况用 | 什么情况不用 |
| --- | --- | --- |
| citycraft | 要一整页有风格的落地页 | 只做后台、组件、局部修补 |
| oil-ui-pro | 界面、组件、后台；要方向对比或按截图打磨 | 只改文案、只改一个颜色 |
| oil-frontend | 要把界面落成能点的代码，动交互、状态、轻动效 | 只出静态页面、只有图片需求 |
| oil-motion | 要 AI 生成连续画面的交互动画 | 纯 CSS/JS 就能做出来的过渡 |
| web-design-guidelines | 页面已经做出来，要验收可读性与可访问性 | 还在定方向、或只是私人草稿 |
| oil-html | 用户点名要那种白底黑字网格的分享文档 | 用户只说「做个页面」 |
| oil-ppt | 要做 16:9 幻灯片 | 滚动网页、单张海报 |
| oil-tone | 有面向读者或观众的文案 | 只调样式、没有对外文字 |
| oil-visual | 要配图、解释图、透明插画 | 页面里已经有真实截图或拟真 UI |
| oil-icon | 要一整套风格统一的图标 | 只要一两个简单图标 |
| image-gen | 要生图或改图（默认走 MCP 的 magpie-image） | 这次不需要图片 |
| beautify-github-readme | 要 SVG 徽章、线条图、仓库首页配图 | 和仓库门面无关 |
| documents 等四个 | 要能下载、能打印的正式文件 | 要的是网页或 HTML |
| kdocs | 要在线协作文档 | 在本地出文件 |

## 按类型调用 SOP

类型和车道是两层，不要混在一起：

- 类型决定“做什么”：笔记整理、文档整理、内容排版、从零写文档、视觉素材、网页与界面。命中哪一类，只读 `sops/` 里对应的那一份。
- 车道决定“用什么产出”：网页、HTML/演示、图片、正式文件。一个笔记任务可能不走视觉车道，只借用车道 ③ 的配图能力。
- 没有对应 SOP 时按底座走，把这次有效的做法记进 `habits.md`；同类任务连续出现两次，再升级成 SOP。

索引、分档和停机点见 [sops/index.md](sops/index.md)。第一份完整 SOP 是 [笔记整理](sops/note-organization.md)。

## 底座（每趟都走）

### 步骤 1 · 问清用途

问这五件事，能推断的自己推断，只问会改变方向的：

1. 给谁看：只有自己、同事、客户，还是公开。
2. 在哪看：手机、电脑、投屏，要不要打印。
3. 看完希望对方做什么或者明白什么。
4. 最想让人记住哪句话；没有就替他提炼一句。
5. 有没有品牌色、logo、参考图；或者「不想像什么样」。

判据：问完能用一句话说出「给谁、在哪看、要他干什么」。用户答不上来就替他定一个，并说明这是假设。

### 步骤 2 · 定方向

- 用户已经说清要什么（品牌色、参考图、别人家的样子）→ 直接定一个方向，三四行说明结构、核心动作、视觉语言和为什么这么选。
- 没说 → 先定一个最合适的；只有用户要看比较、或你确实定不了方向时，才出 2~3 个方向并排给他挑。
- 走 citycraft 的整页落地页：它自带风格库，风格这一层交给它，不用另外跑对比页。
- 需要先看效果图才敢定：用 image-gen 出一两张。
- 有对外文案时同时定文案基调：对读者用「你」还是「我们」，说到多细，哪些词不用。文案多时先让 oil-tone 把标题、按钮和开场定下来，再排视觉。

判据：方向（长相和说法）定下来才往下做。用户说「你定」就直接定，不要反复确认。

### 步骤 3 · 做第一版

- 只做最关键的一屏、一页或一张图，检查过再照它的结构铺开其余的。
- 产物放用户的任务目录；没有项目目录就放当天的日期目录下。

判据：第一版能打开，主要画面和文字都在，标题和按钮读得通。

### 步骤 4 · 看一眼再改

- 真打开或截图看，不要凭代码想象。
- 对照步骤 1 那句话检查：看不看得懂、认不认得出、有没有多余的东西。
- 分头改：文案找 oil-tone，视觉找 oil-ui-pro，交互与状态找 oil-frontend，动效按轻重选 oil-frontend 或 oil-motion。

判据：那句话说得通。连续改三轮还是不对，停下来回头问方向，别继续磨细节。

### 步骤 5 · 交付与自检

```bash
py -3 <技能目录>/scripts/design_check.py check <产物路径或目录>
py -3 <技能目录>/scripts/note_check.py check <笔记路径>
py -3 <oil-tone 目录>/scripts/tone_lint.py <文案文件>
```

- 有阻断项就先改再交。
- `tone_lint.py` 只给措辞提示，不阻断；排版和数据仍要人看。
- 交付时说三件事：文件在哪、怎么打开、哪些还没验证过。

## 车道 ① · 网页与界面

什么时候走：网站、落地页、App 界面、后台、组件，含交互与动效。

顺序：底座 1 → 2（含文案基调）→ 对外文案（oil-tone）→ 选做法（citycraft 整页落地页 / oil-ui-pro 界面组件）→ 交互与动效 → 验收 → 底座 4、5。

**oil-tone（对外文案）**

- 管标题、副标题、按钮、表单提示、空状态、报错和页脚；只要读者会看到，就按它的口径写。
- 先把文案定下来，再排视觉；文案一改，版式要重新看一遍，不能只改字不管挤压。
- 纯视觉、没有任何对外文字的活可以不用。

**citycraft（整页落地页）**

- 入口是它自己的 `SKILL.md`，风格库、区块模板和本地预览都在它的 `references/` 与 `assets/` 里。
- 从导航到页脚整页做完；风格按它的风格库选，不自己另起一套。
- 本机预览需要 Python 3.10+；网页里的外部字体和 CDN 会产生联网请求，要离线就换本地资源。

**oil-ui-pro（界面、组件、后台）**

- 读它自己的主流程：选择范围 → 选择领域 → 步骤 1–5。不要从第 1 步机械重跑。
- 它默认只推荐一个方向、全流程只确认一次；用户明确要比较时才出多个方向。
- 存量项目改界面：先把诊断发给用户再改；不覆盖、不挪动已有页面，要不要换入口问用户。

**oil-frontend（落到能点的界面）**

- 管交互、状态、响应式和轻动效；沿用项目已有的组件、变量和库，不另起一套。
- 纯 CSS/JS 能做的过渡就在这一层做完，不要动 oil-motion。

**oil-motion（AI 生成连续画面的交互动画）**

- 只在需要「主体本身变化」时用：角色转向、产品拆解、材质变化、镜头穿越、一镜到底转场。
- 本地处理已有视频和序列帧需要 Python 3.10+ 与 FFmpeg；要用 AI 生成关键帧或视频时走 ZenMux 的 Key，Key 存进系统凭据库，不写进对话。
- 每次生成都计费，所以先做一小段确认效果再批量生成。

**web-design-guidelines（验收）**

- 页面已经能做出来之后跑一遍，查可读性、可访问性和网页通用规范。
- 它只出问题和建议，不重画页面；要按它的意见改视觉时回到 oil-ui-pro。

备选（不登记，需要时才用）：要**图片式设计稿**而不是能点的页面时用 draw-ui；没装 oil-ui-pro 时退回 oil-ui。

判据：页面在目标视口能打开、主要动作走得通、标题和按钮说得清、我们自己看一眼没有明显问题。

## 车道 ② · HTML 文档与演示

什么时候走：给别人看的 HTML 分享文档，或 16:9 幻灯片。

**HTML 分享文档（oil-html，用户点名时才用）**

- 读它的设计基底与 CSS 设计系统，用自带的 class 搭页面，不够再加页面级样式。
- 硬指标：正文 16px、最小可读字号 14px；总长 2–3 屏；模块不超过 5 个；彩色不超过 2 个色相。
- 需要插画找 oil-visual，文案按 oil-tone。
- 交付前在真实浏览器里看一遍渲染结果；看不到就明说视觉未验证。

**16:9 幻灯片（oil-ppt）**

```bash
<oil-ppt 目录>/scripts/oil-ppt init <项目>
<oil-ppt 目录>/scripts/oil-ppt status <项目> --json
```

- 按返回的 `next` 一次做一件事，做完重新读状态，不要自己跳步。
- 先写逐页大纲（每页一句「讲什么、观众看见什么」），用户看过再一页页做。
- 每页只讲一个判断或一层关系；看不清时先删重复说明或拆页，不靠缩小字号塞内容。
- 正式预览要用户确认；只有用户明确要 PowerPoint 时才导出 PPTX。

判据：文档不超过 3 屏、演示每页一个判断、没有示例文案和占位图。

## 车道 ③ · 图片、图标与插画

什么时候走：要配图、解释图、透明插画、成套图标，或 SVG / 徽章这类矢量素材。

**解释图（一张图自己讲清一件事）**

- 用 oil-visual 的模式 A。先写视觉简报：10 秒内要让人明白什么、画面里有哪些真实物件、它们是什么关系、需要哪几个标签。
- 生成后逐个核对图里的标签，错字、多字、漏字都要整张重新生成，不要另贴一层文字盖住。

**透明插画（要叠进页面或卡片）**

- 用 oil-visual 的模式 B。能直接出真透明背景最好；只能出纯色底时用它的 `scripts/cutout.py` 抠底。
- 验四角真的是透明，细线和内部留白没有被误删。

**成套图标（oil-icon）**

- 先把风格和配色锁成具体色值，再一次 4×4 生成一版。
- 切图后逐个检查：有没有从邻格串进来的碎片、有没有残留灰底、线条粗细和圆角是否一致。

**生图通道（出图与改图）**

- 优先用宿主现成的 MCP 生图能力（`magpie-image`）。这是本机的默认通道，不用另外准备 Key，也不要为了生图去起别的命令行工具或换收费服务。
- 需要脚本入口时用 image-gen：它把生图脚本接到同一条通道上，适合「某个技能是通过脚本调生图」的场合。
- 也可以自己配置生图服务（自选）。怎么配看 image-gen 自己的说明，配置过程不写进这份工作流。
- 通道用不了时只影响生图，其余步骤照常；先把不需要生的部分做完，并说明差哪一项，不要说成「全都做不了」。

**SVG 素材（beautify-github-readme）**

- 只用它的纯 SVG 部分：徽章、线条图、仓库首页配图。
- 仓库上传、远端整理属于另一条工作流，不要在这里做。

判据：图在 3 秒内认得出主体；透明图四角真的透明；图标成套的大小、线条、风格一致。

## 车道 ④ · 正式文件

什么时候走：要 Word、PDF、表格，或要交给别人的演示文件。

- Word / PDF / 表格 / 演示文件用宿主自带的 doc、文档、演示、表格能力（清单里记成「插件提供」）。它们不在本机技能目录里，所以 `wf.py scan` 看不到。
- 在线协作文档走 kdocs。
- 对外文件的标题、摘要、表头、说明按 oil-tone 写；字号、行距和层级仍归文档能力管。
- 笔记整理不走文件排版，先读 [sops/note-organization.md](sops/note-organization.md)。
- 视觉上仍按底座走：先在纸上或草稿里定结构，再落到文件；不要边排边想。

判据：文件能打开、字体不乱、不靠超小字号塞内容。

## 下一步可以补什么

- 给 `design_check.py` 加幻灯片和演示文件专属的检查（每页字数、字号下限）。
- 把 `note_check.py` 扩到 PDF、Word 和截图 OCR 的文本抽取检查。
- citycraft 和 oil-motion 首次实跑之后，把真实命令和参数补进对应车道。
- 把每次翻车的具体现象继续往 `habits.md` 里攒。
