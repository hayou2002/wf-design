# 设计工作流 · 编排手册

本文件只写技能如何组织、阶段如何交接。专项设计方法读取对应技能，不在这里复制。

## 名词速查

- 参考意向：用户想接近的视觉感觉或局部元素，还不是本产品正式设计。
- 关键样板：用真实业务内容做的一屏、一页、一张或一个关键动作，用来低成本确认方向。
- 设计简报：记录任务、参考、约束和交付终点的一页以内说明。
- 交互动画：界面对操作的反馈与过渡；视频：连续镜头内容，两者分开组织。

## 1. 明确任务

先形成设计简报，字段不全时只问会改变参考筛选或实现的问题：

```text
产物与交付：要什么格式，做到设计稿还是可用成品
用途与受众：给谁，在什么设备或场景使用
核心内容：必须出现哪些真实内容，最关键的信息或动作是什么
现有约束：品牌、参考、设计体系、技术栈、尺寸、语言和不可改部分
参考意向：已选链接/截图/编号，以及喜欢或不喜欢的局部
样板范围：这次只验证哪一屏、哪一页、哪张图或哪个动作
```

用户答不上来时先写假设并标明，不用设计术语追问。个人形象任务先读 miao-visual；对外文字由 oil-tone 负责表达，排版由产物技能负责。

## 2. 选择参考

按以下顺序执行，找到合适候选就停止扩搜：

1. 用户提供的参考与项目现有设计体系。
2. Oil 本地资源：艺术官网查 oil-art-landing；其余界面用 oil-ui-pro 的方向探索与对比能力。
3. [参考资源索引](references-library.md) 中与产物匹配的库。
4. GitHub 与更广泛网页搜索。

本地没有合适参考时，先检查用途、产物、平台和关键偏好是否足以筛选；不足就集中问一次，再外搜。默认给 3 个差异明确的候选，找不到时不拿无关结果凑数。

候选尽量汇总到同一对比页。Oil 预览用 oil-ui-pro 的对比工具；外部库给对应设计详情页，并尽量补截图或演示；GitHub 查 README 图片、项目官网、在线 Demo、Storybook 或视频。每个候选只用日常语言说明：整体感觉、适合什么、主要区别。

**停点：等用户确认参考意向。** 可整体选择，也可写“A 的布局 + B 的配色 + C 的按钮”。把选择补进设计简报，不开始完整制作。

## 3. 确认样板

按产物选择最小但足以决策的范围：

| 产物 | 关键样板 |
| --- | --- |
| Word、PDF | 封面或首页，加一个代表性正文页；短文档可只做代表性页面 |
| PPT | 封面、一个内容页、一个关键图示页；简单演示可减少 |
| 网页 | 首屏或最关键一屏；按用户需要交视觉稿或可运行页面 |
| 移动 App | 一个核心页面与最关键的一步操作 |
| 桌面应用 | 主窗口与核心工作区 |
| 界面模块 | 正常状态，必要时加一个关键交互状态 |
| 图片 | 一张关键画面 |
| 交互动画 | 一个关键动作的可操作原型或短预览 |
| 视频 | 关键分镜、静帧或几秒试片 |

样板只包含验证方向所需的真实内容，不接完整业务、不铺全部页面、不做全部响应式和边界状态。艺术官网按 oil-art-landing 做首屏视觉样板；其余技能按其适合的形式呈现。

**停点：等用户确认样板。** 修改只发生在样板范围。整体方向改变时回到阶段 2；局部调整则继续改同一样板。

## 4. 完整制作

- 用户只要设计稿、图片或文档时，到对应成品就停止，不默认写应用代码。
- 艺术官网由 oil-art-landing 交视觉基准给 oil-ui-pro；城市主题整页用 citycraft；普通网页、App、桌面应用与模块用 oil-ui-pro。
- 可运行界面的交互、状态和响应式交 oil-frontend；交互动画不要交给视频技能。
- 连续镜头、角色运动和产品视频交 oil-motion；生成与计费按该技能自己的规则执行。
- 正式文件用宿主文档、PDF、演示或表格能力；HTML 演示用 oil-ppt，点名风格时才用 oil-html。
- 图片按用途选 oil-visual、oil-icon、image-gen 或 beautify-github-readme；小妙和啊呜必须按 miao-visual。
- 后续页面和状态沿用已确认样板。需要换方向时先停下说明影响，不悄悄重做。

## 5. 验收交付

先按 [产物验收卡](acceptance.md) 做对应检查，再运行完整性工具：

```bash
py -3 <wf-design>/scripts/design_check.py check <产物路径或目录>
py -3 <wf-design>/scripts/note_check.py check <笔记路径>
py -3 <oil-tone>/scripts/tone_lint.py <文案文件>
```

完整性脚本不能替代视觉、交互与任务验收。网页成品按需用 web-design-guidelines；其他产物用对应技能的渲染、预览或验证工具。无法真实查看时明确写“视觉未验证”。

交付说明只保留：交付文件、打开方式、已验证项、未验证项。

## 功能与规则怎么增补

1. 有现成技能：验证后引用，登记负责阶段、输入、输出和交接对象。
2. 只有一两点值得采用：蒸馏进本手册对应阶段，不引用整个技能。
3. 同一主题的通用判断增多：再独立成 references 文件，并从对应阶段链接。
4. 方法完整、会重复使用或需要工具：按 oil-skill-creator 新建技能，再路由进来。
5. 个人偏好与踩坑：写 habits.md，不写成所有用户的默认审美。
